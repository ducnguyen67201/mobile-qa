# Phase 05 — A readable test library

Build the complete customer author → review → release plan → build → run → evidence flow using existing Mantine components and generated Rust transport contracts. The library must be useful before an APK is uploaded. Cases, Suites and Release plan are distinct, approachable workspaces. Immutable versions and two independent review purposes must be understandable without reading JSON.

Continue the warm paper canvas, forest navigation and restrained green accents. Use an editorial content column, numbered action/check cards and quiet readiness summaries. Visual hierarchy should answer: What am I testing? What should happen? Is this exact version reviewed? What will run? Expected results come before advanced evidence selectors. Responsive stacked controls, meaningful empty states and readable long identifiers are required.

Functional completion, typed runtime boundaries, explicit save, conflict preservation, keyboard controls and no cross-workspace draft leakage are hard requirements. No invented metrics, automatic approval, raw JSON editor, mock production content or direct browser-to-emulator calls. Existing report and simulation warnings stay visible. No draft bodies in browser storage.

GAN loop: Generator + independent Evaluator; up to 10 iterations, weighted threshold 7.5. Code-only evaluation because existing browser admin-policy denial remains binding. Scores are provisional source assessment, not observed rendered quality. No alternate browser access. Deterministic checks wait until the root agent declares the full source/test/config batch complete. Old phase 03 brief/rubric/state is retained in phase03/ and historical feedback remains intact.
