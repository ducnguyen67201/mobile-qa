# App setup dashboard design brief
Build spec 03 from .claude/PRPs/plans/completed/03-app-setup.plan.md using packaged Mantine components. Calm, exceptional professional Android QA workbench: warm off-white canvas, dark forest navigation, restrained green accents, precise typography and spacious hierarchy. Use Mantine AppShell/Drawer and standard packaged controls; centralize the theme and keep product code readable. Copied primitives and long class-string styling are rejected by the user. The central app detail should make uploaded build identity and trustworthy validation status immediately clear. Design considered empty/loading/error/sign-in states, not just the populated screen. Originality should arise from purposeful editorial layout and polished workflow details, not novelty that obscures usability.

Required: sign-in, protected shell, apps list/create, app detail/environment, APK transfer/finalization/recovery, build history/status, settings. Preserve real generated API contracts and truthful not-checked device readiness. Tests/Runs remain labeled placeholders. Functional completion is mandatory: design skill's preference for incomplete beauty does not override the user's agreed feature.

Evaluation mode: code-only due to existing explicit browser admin-policy denial. Do not launch a browser or bypass it. No claims of observed rendered design. At most 10 generator/evaluator cycles; weighted threshold 7.5. Review source while authoring; no build/test/lint/format/generation/runtime until root declares all scoped edits complete. No commits/push. Use code-only provisional scoring and retain rendered acceptance gate.
